# Push-уведомления (Firebase Cloud Messaging)

Зачем это. На телефоне фоновая проверка работает через фоновую службу, а
Android за такую службу обязывает показывать постоянное уведомление и скрыть
его не даёт. Push решает задачу с другой стороны: сообщение приносит сама
система, служба не нужна, уведомления в шторке нет, батарея не тратится, и
приходит оно даже когда приложение выгружено.

**ПК ничего из этого не касается.** Он не получает push и не нуждается в
Firebase: окно можно держать открытым, есть значок в трее, и Windows не
убивает фоновые процессы так, как это делает Android. Единственное, что
появилось на стороне ПК, — миграция 22, создающая таблицу `device_tokens`.
Сам он ей не пользуется; миграция общая потому, что журнал
`schema_migrations` один на всех клиентов, и номер 22 обязан означать везде
одно и то же.

Пока ничего из описанного ниже не сделано, всё работает как раньше:
приложение собирается, фоновая проверка идёт, push просто спит.

---

## 1. Проект Firebase (делается один раз, в браузере)

1. https://console.firebase.google.com → **Создать проект**. Google Analytics
   не нужен.
2. В проекте → **Добавить приложение** → Android.
3. Имя пакета — **ровно** `com.pismo.messenger`. Не совпадёт — push не
   придёт, и без единой ошибки: Firebase просто не узнает приложение.
4. Скачать **`google-services.json`** и положить в `app/google-services.json`
   (рядом с `app/build.gradle.kts`).
5. Настройки проекта → **Сервисные аккаунты** → *Создать закрытый ключ*.
   Скачается json — это ключ для сервера, он даёт право рассылать push
   вашему приложению. В репозиторий его класть нельзя.

## 2. Сборка приложения

Ничего включать не нужно: `app/build.gradle.kts` сам видит
`google-services.json` и подключает Firebase. Нет файла — собирается без
него, как сейчас.

Файл приватный: добавьте его в `.gitignore` и держите вне репозитория.
Сборка в GitHub Actions его не увидит — значит, APK оттуда будет **без
push**. Чтобы push попал в релиз, файл нужно класть на машину сборки
(например, секретом в Actions).

## 3. Сервер

**Коротко: одной командой.** Положите ключ сервисного аккаунта в
`/opt/pismo-ws/firebase.json` и запустите:

```bash
curl -fsSL https://raw.githubusercontent.com/pismodb78-bit/pismo_messendger/claude/pismo-android-version-qd5fxr/ws-server/install-push.sh | sudo bash
```

Скрипт обновит `server.js` и `push.js`, поставит пакеты, пропишет настройки в
systemd, перезапустит службу и сам скажет, включился push или нет. Запускать
повторно безопасно.

Если сервер лежит не в `/opt/pismo-ws` или служба называется иначе:

```bash
curl -fsSL …/install-push.sh -o install-push.sh
DIR=/ваш/путь SERVICE=имя-службы sudo -E bash install-push.sh
```

Доступ к базе в скрипте подставлен из `ip.txt`. Если на сервере пароль
другой — поправьте переменные `DB_*` в начале файла.

### То же самое руками

На VPS, рядом с `server.js`:

```bash
cd /opt/pismo-ws
npm install firebase-admin mysql2
cp ~/firebase-service-account.json /opt/pismo-ws/firebase.json

# Владелец — тот, от кого работает служба. Без этого файл остаётся
# за root, а node падает с «EACCES: permission denied».
chown "$(systemctl show -p User --value pismo-ws)" /opt/pismo-ws/firebase.json
chmod 600 /opt/pismo-ws/firebase.json
```

Две переменные окружения — в юнит systemd (`/etc/systemd/system/pismo-ws.service`),
секция `[Service]`:

```
Environment=FIREBASE_CREDENTIALS=/opt/pismo-ws/firebase.json
Environment=PISMO_DB=mysql://ПОЛЬЗОВАТЕЛЬ:ПАРОЛЬ@5.181.23.167:3307/bdauth
```

Затем:

```bash
systemctl daemon-reload && systemctl restart pismo-ws
journalctl -u pismo-ws -n 20
```

В логе должно появиться `[PUSH] включён`. Если видите `[PUSH] выключен: …` —
там же написано, чего не хватает.

## 4. Проверка

1. Войти в приложение на телефоне (при входе адрес устройства записывается в
   `device_tokens` — проверить можно запросом `SELECT * FROM device_tokens`).
2. Закрыть приложение полностью, смахнуть из недавних.
3. Написать с ПК.
4. Уведомление должно прийти.

## 5. Когда заработает — выключить фоновую проверку

Настройки → **Фоновая проверка сообщений** выключить. Постоянное уведомление
исчезнет, а сообщения продолжат приходить — уже через push.

---

## Чего в push НЕТ

Текста сообщения. Он лежит в базе зашифрованным, ключ есть только у
клиентов. Расшифровать его на сервере было бы можно — и тогда сервер начал
бы читать переписку. Поэтому push несёт только «кто и куда написал», а за
содержимым клиент идёт в базу сам. В шторке из-за этого вместо текста будет
«Новое сообщение».

Каналы серверов push пока не шлют — только личные сообщения и группы.
